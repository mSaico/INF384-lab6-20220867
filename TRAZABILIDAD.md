## Cambios a la propuesta de Kiro

| Documento | Qué propuso Kiro | Qué cambiaste | Por qué |
| --- | --- | --- | --- |
| tasks.md | Tarea 3.1: comprobar el límite de 150 elementos **después** de validar el formato de cada elemento | Comprobar el límite **inmediatamente después** de verificar que es un array y **antes** de recorrer los elementos | La propuesta reintroducía el hallazgo 1: con 5000 códigos el servidor recorría toda la lista antes de rechazarla |
| requirements.md | 5.3 "DONDE se revise el repositorio, EL sistema DEBE mantener los secretos fuera… según `config/ejemplo.env`" | "SI gitleaks detecta un secreto en el historial del repositorio, EL pipeline DEBE fallar" | Era vago y no se podía probar (mal uso de DONDE), y remitía a un archivo que contenía una clave real |
| design.md | Gates con etapa **solo PR** | Etapa **PR y push a main** | En este repo se integra con push directo a main; con solo PR los gates no revisarían esos cambios y la política aplica a todo lo que llega a main |
